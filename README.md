# Вече — мессенджер на GitHub Pages

Сайт-мессенджер: регистрация по имени и паролю, личные чаты, группы, голосовые звонки,
стикеры, правка и удаление сообщений, блокировка, push-уведомления.
Всё бесплатно. Карта не нужна.

**Как это устроено:**
- Сайт лежит на **GitHub Pages** (это просто файлы).
- Аккаунты и сообщения хранит **Firebase** (бесплатный тариф Spark).
- Push, когда сайт закрыт, шлёт маленький сервер на **Cloudflare Workers** (бесплатно).

Делайте шаги по порядку. Это примерно 30 минут.

---

## Шаг 1. GitHub

1. Зайдите на https://github.com и создайте аккаунт (если нет).
2. Нажмите **New repository**. Имя, например, `vech`. Выберите **Public**. Нажмите **Create repository**.
3. Нажмите **uploading an existing file**. Перетащите туда **все файлы** из этой папки
   (`index.html`, `app.js`, `config.js`, `sw.js`, `worker.js`, `firestore.rules`,
   `manifest.webmanifest`, `icon.svg`, `icon-192.png`, `icon-512.png`).
4. Нажмите **Commit changes**.

## Шаг 2. Проект в Firebase

1. Откройте https://console.firebase.google.com (нужен аккаунт Google).
2. Нажмите **Create a project** (Создать проект). Имя любое. Google Analytics можно выключить.
3. Когда проект создан, нажмите значок **`</>`** (Web app / веб-приложение).
   Имя любое. **Firebase Hosting не нужен.** Нажмите **Register app**.
4. Появится блок `firebaseConfig = { ... }`. **Оставьте эту страницу открытой.** Он понадобится в шаге 4.

## Шаг 3. Вход и база данных

1. Слева: **Build → Authentication → Get started**. Во вкладке **Sign-in method** выберите
   **Email/Password**, включите первый переключатель (Enable) и нажмите **Save**.
2. Слева: **Build → Firestore Database → Create database**.
   - Место (location): выберите `eur3 (europe-west)` — это Европа, ближе к вам.
   - Режим: **Production mode**. Нажмите **Create**.
3. Откройте вкладку **Rules**. Удалите всё, что там есть. Вставьте **весь** текст из файла `firestore.rules`.
   Нажмите **Publish**.

Эти правила важны: они защищают данные и запрещают заблокированным писать.

## Шаг 4. Ключи в config.js

1. В GitHub откройте файл `config.js` и нажмите значок карандаша (Edit).
2. Замените значения `ВСТАВЬТЕ...` на значения из `firebaseConfig` (шаг 2).
   Кавычки оставьте. Нужны все шесть: `apiKey`, `authDomain`, `projectId`, `storageBucket`,
   `messagingSenderId`, `appId`.
3. Нажмите **Commit changes**.

Эти ключи не секретные. Данные защищают правила из шага 3.

## Шаг 5. Включить сайт

1. В репозитории GitHub: **Settings → Pages**.
2. **Source:** Deploy from a branch. **Branch:** `main`, папка `/ (root)`. Нажмите **Save**.
3. Через 1–2 минуты сверху появится адрес: `https://ВАШ-ЛОГИН.github.io/vech/`.
4. **Важно.** Вернитесь в Firebase: **Authentication → Settings → Authorized domains → Add domain**.
   Добавьте `ВАШ-ЛОГИН.github.io` (без `https://` и без `/vech`).

Откройте адрес сайта. Зарегистрируйтесь. Откройте сайт ещё раз в другом браузере, создайте второй аккаунт и напишите первому.

Если на этом шаге всё работает, то сообщения, группы, стикеры, блокировка и звонки (когда оба онлайн) уже готовы.

## Шаг 6. Push-уведомления и звонки, когда сайт закрыт (по желанию)

Нужен маленький бесплатный сервер. Без него сайт тоже работает, но уведомления приходят только пока сайт открыт во вкладке.

1. Зайдите на https://dash.cloudflare.com и создайте бесплатный аккаунт (карта не нужна).
2. **Workers & Pages → Create → Create Worker.** Имя: `vech-push`. Нажмите **Deploy**.
3. Нажмите **Edit code**. Удалите весь код. Вставьте **весь** текст из файла `worker.js`. Нажмите **Deploy**.
4. Создайте хранилище: **Storage & Databases → KV → Create** (имя любое, например `vech`).
5. Вернитесь в Worker `vech-push` → **Settings → Bindings → Add → KV namespace**.
   - **Variable name:** точно `VECH` (большими буквами).
   - **KV namespace:** то, что вы создали. Нажмите **Save/Deploy**.
6. **Settings → Variables and Secrets → Add** (тип Text):
   - `FIREBASE_PROJECT_ID` = ваш `projectId` из Firebase.
   - `ALLOW_ORIGIN` = `https://ВАШ-ЛОГИН.github.io` (без `/vech` и без `/` в конце).
   - (по желанию) `VAPID_SUBJECT` = `mailto:ваша-почта@gmail.com`.
   Нажмите **Deploy**.
7. Скопируйте адрес Worker, он вида `https://vech-push.ВАШ-ЛОГИН.workers.dev`.
   Откройте его в браузере: должно быть `{"ok":true,...}`.
8. В GitHub в `config.js` вставьте адрес в `pushWorker: "..."`. Нажмите **Commit changes**.
9. Откройте сайт → **Настройки → Уведомления → Включить push**. Разрешите уведомления.
   Сделайте это на **каждом устройстве** (и друзьям тоже).

**Как это работает со звонками:** когда вам звонят, а сайт закрыт, приходит громкое уведомление
«Входящий звонок». Нажмите на него: сайт откроется и покажет кнопку «Принять».
Звонок ждёт 60 секунд. Принять звонок, не открывая сайт, нельзя: браузеру нужна открытая страница.

**iPhone:** push работает только в iOS 16.4 и новее, и только если сайт добавлен на экран «Домой»
(Safari → Поделиться → На экран «Домой»). Откройте его оттуда и включите push.

## Звонки

Звонки идут напрямую между устройствами (WebRTC). Браузер попросит микрофон.

- Дома, на Wi-Fi: обычно работает сразу.
- Если звонок «Не удалось соединиться» (часто на мобильном интернете или в офисе): нужен TURN-сервер.
  Бесплатный есть у https://www.metered.ca/tools/openrelay/ (нужна регистрация).
  Добавьте его в `config.js`, в список `iceServers`:
  `{ urls: "turn:АДРЕС:80", username: "ЛОГИН", credential: "ПАРОЛЬ" }`

## Что важно знать честно

- **Я проверял сайт на имитации Firebase**, не на настоящем. Все функции там работали
  (регистрация, чаты, стикеры, правка, удаление, блокировка, звонок голосом между двумя вкладками,
  смена имени, подтверждение входа). На настоящем Firebase может что-то отличаться.
  Если при настройке видите ошибку, пришлите мне её текст, я исправлю.
- **Россия.** Я не могу проверить, что открывается у ваших друзей без VPN. Сайты Google (Firebase),
  GitHub и Cloudflare там иногда работают нестабильно, и push-сервисы браузеров тоже.
  Сначала проверьте, что сайт открывается у друга.
- **Лимиты бесплатных тарифов.** Firebase: 50 000 чтений и 20 000 записей в день. Для 5–15 друзей хватает.
  Cloudflare KV: 1 000 записей в день, это примерно 500 push-уведомлений в день.
  Если лимит кончился, всё снова заработает завтра.
- **Защита.** Правила Firebase по-настоящему запрещают чужим читать ваши чаты и заблокированным писать.
  А вот подтверждение входа с другого устройства («Это я» / «НЕТ, ЭТО НЕ Я») — это защита уровня страницы:
  тот, кто знает пароль и умеет править код, может её обойти. IP-адрес и HWID сайт получить не может.
  Не используйте здесь настоящие пароли.
- **Приватность.** Сообщения хранятся в Firebase в обычном виде (не сквозное шифрование).
  Все зарегистрированные люди видят друг друга в поиске.
